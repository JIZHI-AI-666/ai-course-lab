# 作业 3 · W10 预习：Function Calling / MCP / 普通 API 调用各一句话辨析

## 一、三者辨析（各一句话）

**Function Calling 是模型侧机制**——模型读到提示词里的工具清单后，决定「调哪个工具、传什么参数」并以 JSON 输出意图，但从不亲手执行：本周 `tool_agent.py` 里模型输出 `{"tool": "hsk_level", "args": ["把"]}` 后，真正查 CSV 的是我们的 Python 函数。

**MCP 是工具侧协议**——它不决定模型怎么想，而是把工具的发现、描述、调用统一成标准协议，让工具可以由别人提供、跨应用复用：本周工具写死在 `TOOLS` 字典里、和代码同生共死，MCP 要解决的是「工具不在本机、由第三方提供时接口长什么样」。

**普通 API 调用是程序侧固定管线**——调不调、调哪个、传什么全由程序员写好的代码路径决定，模型至多在被喂进来的资料里打转：对照 W8 的 `use_rag=True/False` 开关，那是由 `if` 分支决定的检索，不是模型的决定。

一句话串起来：**普通 API 是"程序员决定"，Function Calling 是"模型决定调什么"，MCP 是"让别人标准地提供工具"**——三者分属程序侧、模型侧、工具侧，不是同一层的竞争方案。

## 二、希望 MCP 帮我接上的 2 个外部工具

**1. 权威词典检索（汉英双语词典 API）**
课程生词表只有 13 词，`hsk_level` 查不到的词只能答「未找到」；接一个权威词典工具后，备课遇到表外词（如《愚公移山》里的"叩石垦壤"之外的任意文言词）可以当场查拼音、英译和例证，且来源可核对——和本周「确定数据靠查表不靠模型记」是同一个原则，只是把表从本地 CSV 换成了外部标准源。

**2. 日历/课表工具（读写日程）**
备课安排、答疑时段、作业截止提醒现在全靠手动；接上日历工具后可以直接对助教说「把下周的《愚公移山》文化拓展课排在周四下午并提醒学生」，由模型决定调创建日程还是查忙闲。选它的另一个原因：日程是典型的**写操作**，必须有明确的参数校验与用户确认——正好检验 W10 讲的 MCP 工具安全边界，也延续本周「越权表达式被拒绝」的思路。
