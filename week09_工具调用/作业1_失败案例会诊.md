# 作业 1 · 失败案例会诊：口语式复合问句「答一半 + 编造时间」

按讲义会诊方法做：**把失败时的原始模型输出、解析结果、工具返回值三段都留在轨迹记录里，先复现再改提示词，不凭感觉调**。本会诊选的类型是会诊表第 4 类「复合问句答一半」，并连带记录了同批样本里的「循环不收口」。

原始数据：[homework1_failures_20261116.json](evidence/homework1_failures_20261116.json)，同一口语式问句 `--repeat 6` 连跑 6 次的真实采集，未改写模型输出。

## 一、失败现象（6 次连跑统计）

| run | 首轮模型输出 | 调用 get_time | 最终回答 | 定性 |
|---|---|---|---|---|
| 1 | `{"tool": "hsk_level", "args": ["把"]}` | 否 | 「现在是14:25。」 | **答一半＋编造时间** |
| 2 | `{"tool": "hsk_level", "args": ["把"]}`（第二轮补 `get_time`） | 是 | JSON 原文（max_calls 收口） | 循环不收口 |
| 3 | 同 run1 | 否 | 「现在是几点？现在是13:15。」 | 答一半＋编造时间 |
| 4 | 同 run1 | 否 | 「……现在是北京时间13点10分。」 | 答一半＋编造时间 |
| 5 | 同 run1 | 否 | 「现在是 14:22。」 | 答一半＋编造时间 |
| 6 | 同 run2 | 是 | JSON 原文（max_calls 收口） | 循环不收口 |

**6 次里只有 2 次真正调了 `get_time`；4 次没查时间却报了一个具体时刻。**采集发生在 13:41–13:42（run2 的 `get_time` 真实返回 `2026-11-16 13:41:13`），而编造的时刻是 14:25 / 14:22 / 13:15 / 13:10——全是模型凭「现在大概几点」的语感生成的，不是系统时间。

## 二、会诊主案例：run 1（三段齐全）

1. **原始模型输出**（第一轮）：

   ```json
   {"tool": "hsk_level", "args": ["把"]}
   ```

2. **解析结果**：`parse_calls` 解析出 1 个合法调用 `hsk_level('把')`；没有编造工具名，参数格式正确——**解析层没有失败，失败在决策层**。
3. **工具返回**：`把 是 3 级`
4. **最终回答**：`现在是14:25。`——只答了等级的一半没了下文，时间部分直接编造。
5. **错误定性**：问句是口语式复合问（'把'字是几级？现在几点？），模型第一轮只点名了 `hsk_level`；第二轮拿到「把 是 3 级」后没有再调 `get_time`，而是顺着对话惯性补了一句时间——**没有数据支撑的确定性事实**，属会诊表第 4 类「复合问句答一半」，且踩中附带的幻觉风险（「时间没查却编一个假时间」）。

## 三、原因分析

- **问句措辞**：口语式复合问没有把两件事拆成可独立执行的编号指令，1.5B 模型把它理解成了「先答第一个」。
- **回喂措辞**：工具返回消息「工具返回：把 是 3 级。请据此作答。」没有告诉模型「还有一件没办」，小模型就把这当成完整问答收口了。
- **规模因素**：讲义教师机 8B 模型实测五连跑全对；本机 1.5B 在同款问句上 6 连跑只有 2 次办全——模型规模直接决定这类多步规划能力的下限。

## 四、约束改法（与验证）

| 改法 | 针对 | 验证结果 |
|---|---|---|
| **问句改编号列表式**（「请依次查询两件事：1. … 2. …」） | 答一半 | 当堂轨迹 1：模型并列点名两个工具、最终回答两件全对（[trace_run_20261116.json](evidence/trace_run_20261116.json)）；与 run1–5 形成同机同模型的对照组 |
| **回喂文案写明「结果已是最终数据、请直接作答」**（`FEED_TEMPLATE`） | 循环不收口 | 对照实验：原文案 0/5 正常收口 → 新文案 5/5（见 [作业 2](作业2_第4个工具_课文难度评估.md) 第二节） |
| **一轮内执行模型点名的全部工具并合并回喂**（骨架已内置） | 并列调用被丢弃 | 骨架行为，轨迹 1 已实证；若一轮只执行第一个，第二个调用会被丢弃、模型下轮复读 |
| **max_calls=2 到顶强制收口** | 无限烧 token | run2/run6 收口生效，代价是最终回答为 JSON 原文——防御生效但体验未修好，如实记录 |

## 五、结论

这类失败**不该靠换问法藏起来**：口语式问句是学生真实会问的形态，失败样本恰好证明「约束必须写在程序和提示词里，不能指望模型自觉」。可执行的两条改法都已落地：问句措辞是使用方约定（已写进 README 怎么用），`FEED_TEMPLATE` 是程序侧约束（已写进 `tool_agent.py` 并注明缘由）。剩余未解的是「模型歪曲拒绝信息」（见作业 2 轨迹 B），在 1.5B 规模上暂无低成本修法，升级模型或换用云端 `deepseek-chat` 口径后应复测。
