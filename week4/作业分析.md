# 第四次课作业分析与完成说明

## 一 作业目标

本次作业不是只让程序“能回答”，而是要证明你理解第一次 API 调用的完整过程：程序读取环境变量中的密钥，向模型发送问题和参数，接收回答与 token 用量，把过程留在日志中，并能解释 `temperature` 和 `max_tokens` 的作用。

## 二 讲义中的验收点

| 验收点 | 本完成版的对应实现 |
|---|---|
| 命令行接收问题并打印答案 | 直接运行脚本并传入问题 |
| 3 个学科问题 | `--batch` 自动运行 3 个国际中文教育问题 |
| 对话日志 | 每次真实调用追加到根目录 `chat_log.txt` |
| 参数体验 | `--experiment` 对比 4 组参数并生成 `week4_实验记录.md` |
| token 与费用 | 记录输入、输出、总 token；传入当天官方单价后自动估算 |
| 密钥安全 | 只从 `.env` 读取，`.gitignore` 排除 `.env`，代码不含真实密钥 |
| 友好报错 | 覆盖未安装依赖、缺密钥、认证失败、限流或余额不足、超时、连接失败 |
| 可验证性 | 附带 4 个无网络单元测试，检查参数传递、用量提取和费用公式 |

## 三 为什么不能替你伪造最后两项结果

`chat_log.txt` 中的三个回答、真实 token 数、耗时和费用必须来自你自己的 API 调用。没有你的个人密钥时，完成版会保留“待运行”状态，不会编造结果。你只需按 README 配置 `.env`，依次运行 `--batch` 和 `--experiment`，这些证据会自动生成。

## 四 提交建议

建议提交 `week04_API/week4_api_bot.py`、`week4_实验记录.md`、`requirements.txt`、`.env.example` 和 `.gitignore`。不要提交 `.env`。`chat_log.txt` 按原代码包规则被忽略，可课堂展示；如果教师明确要求提交日志，应先检查其中没有密钥或个人敏感信息，再按教师指定方式提供。
