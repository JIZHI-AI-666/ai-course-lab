# 作业 2 附：README 里「已知问题」为什么要诚实写（200 字）

README 的「已知问题」不是自我检讨，而是给使用者的边界说明。别人照着我的 README 装一遍，最可能踩的坑就写在那一段里：没启动 Ollama 会报错、没配密钥时云端不可用、知识库只覆盖《等级标准》节选、0.5B 模型会把「累计词汇 3245」答成 1000、本机嵌入模型标签可能是 `nomic-embed-text:w7-f16`。写出来，读者能提前绕开，或者知道该换哪条路；不写，他就会在演示现场撞上，然后以为是我的代码坏了。

更重要的是，「已知问题」是「我真跑过」的证据。没跑过的人写不出「0.5B 会把四级词汇说成 1000」这种具体数字——我自己也是先跑出这个错，才敢把它写进 README。

还有一点：本次互评别同学的仓库时，我照着对方的 README 装依赖，在根目录执行 `pip install -r requirements.txt` 直接报错，实际文件在子目录里。对方没有写清楚这一点，我第一次就卡住了。如果对方把这类限制写明白，我就能一次装对。

所以我坚持：主动写限制不是给作品减分，而是把「能跑到什么程度」说清楚。这既是对读者负责，也是对自己负责——将来我自己回来维护时，不用重新踩一遍。
