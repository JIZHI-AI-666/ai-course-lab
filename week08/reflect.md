# 第 8 周反思（reflect.md）

写于 2026-11-11。对照 LangChain 官方 2-Step RAG 文档与 llm-universe C3/C4，回答任务单三个问题。

## ① 我的 rag_qa.py 与官方 2-Step RAG 差在哪一步？是没做、还是做法不同？

五步都在，但有一步**做法不同**、两步**没做**。

做法不同的是 **Store**。官方与 llm-universe 都把索引当静态产物：建好就存着，下次直接加载。我多了一层 `corpus_signature()`——把语料内容、嵌入模型、分块配置、章节切分版本一起做 sha256，摘要变了就换集合名，`get_store(rebuild=True)` 还会先 `delete_collection()` 再重建。加这层是因为我真踩过：换语料后旧索引还在，新旧资料混着答，答案看起来有依据，其实依据是上一版资料。官方文档没讲这个，但这是「组件可替换」的真实代价——组件能换，索引的失效策略得自己补。

没做的是两处，都在 llm-universe C4 里明确列着而我这边没有：

- **4.2.5 向检索链添加聊天记录**。我的 `answer()` 是单轮的，第二轮追问「那它的难点呢」这类指代，检索端接不住。
- **4.2.6 带有信息压缩的检索链**。片段一多提示词就长。我的做法是固定 k=3 且在 `build_prompt()` 里限死 150 字——这是**用「少检索」绕开「压缩」问题，属于规避不是解决**。真要上多轮，得按 token 预算裁剪或摘要片段。

另外 C4 的 4.3 Streamlit 部署我没做，本周按计划留到 W15。

## ② 如果要从 2-Step 走到 Agentic RAG，我需要先补上什么能力？

官方说得很直接：Agentic RAG 需要的唯一东西，是**给 agent 一个或多个能取外部知识的工具**（`The only thing an agent needs is access to one or more tools that can fetch external knowledge`）。示例里就是一个 `@tool` 装饰的 `fetch_url`，加上 `create_agent(model=..., tools=[...])`。

所以我要补的是**工具调用能力**，这正是 W9 的内容。对照我的代码，缺口很具体：

1. **函数签名与 schema**。官方用 `@tool` + docstring 生成参数 schema。我要把自己已经写好的两个工具——查生词表、算分——按同样方式暴露出去：`word`/`level`、以及 `answers`/`key`/`items`。
2. **工具返回值的边界**。官方示例里工具返回的是原始文本，交给模型自己消化。但我的两个工具必须返回**结构化事实**（等级、分数），算术和查表由代码做，模型只负责把「8 题对 6 题」翻译成教学建议。否则就重演 W7 那个失败：模型把四级累计词汇 3245 答成 1000。
3. **检索从「固定先做」变成「模型决定做不做」**。现在是 `use_rag` 布尔开关，检索总在生成前。Agentic 要把 `retrieve()` 包成一个工具，让模型自己决定调不调、什么时候调、调用几次。

第 3 点是真正的架构变化。前两点是补接口，第 3 点是把「流水线」拆成「带工具的循环」。官方文档也提到 Agentic RAG 的延迟不固定——因为调用次数不再有上限。这个代价我得在 README 里写清楚，不能等到 W9 才发现。

## ③ llm-universe 没有 LICENSE 文件，为什么我只能参考思路、不能复制它的代码？这与 .env 不入仓的红线有什么共同点？

我实际查了：仓库根目录 `LICENSE`、`LICENSE.txt`、`LICENSE.md`、`license` 四种命名全部 404，**确实没有许可证文件**。按默认规则「保留所有权利」——我能读、能学思路、能署名引用，但复制它的代码进自己仓库，就变成未经许可再分发，是侵权。

**与 .env 红线的共同点：两者都不是「技术问题」，而是「规则问题」，而且都靠默认规则兜底。**

具体说：

- **默认规则在保护使用者**。没有 LICENSE，默认就是全部权利保留，所以我不复制。没有 LICENSE 保护密钥，`git status` 里出现 `.env` 就是泄露，没有「默认它是安全的」这回事。
- **两者都会在「我不小心」时造成不可逆后果**。误复制一段代码，事后删掉也不等于没侵权过；误提交一次密钥，删掉提交也已经在历史里。都必须**在事前**挡住。
- **代价是不对称的**。守规矩的成本是几行 `.gitignore` 和一句「仅参考思路」；破坏规矩的成本可能是别人的账号被盗用，或一份作品集变成抄袭。讲义把这两件事放在同一节课讲「许可证进课堂」，不是并列的两个知识点，而是同一个道理的两个例子。
- **诚实声明是最低成本的对冲**。我在这份作业里写明「RAG 流水线设计参考 LangChain 官方 Retrieval 文档；知识库助手结构参考 Datawhale llm-universe C3/C4（仅参考思路，未复制代码）」，并附上两个链接。这一句话不能替代遵守规则，但它让读者知道边界在哪，也让评审能核对。

**如果 llm-universe 挂了 LICENSE（Apache 2.0 或 MIT），我能不能抄？** 仍然不能整包搬运当作自己的作业——但那时的约束是「署名 + 保留许可声明 + 遵守分发条款」，而不是「只能读」。**有无 LICENSE 决定了规则的起点，不决定我可以不劳而获。** 这也是课程把它和 Apache 2.0 / MIT 区别讲在一起的原因。

本次按 **C 路径**完成（浏览器读文档，不改 v1.0 主线代码）。但我机器 16GB+、本地模型与嵌入都能跑，所以「只读」这条对我不是借口——五步映射表的第三列每一行都对着我实际跑通的 `rag_qa.py` 源码核对过，包括 `corpus_signature()` 这种官方文档里没有、纯粹是自己踩坑加出来的设计。**C 路径限制的是提交物，不是核对深度。**

### 我最想做的那个改造：把拒答从「提示」变成「硬约束」

按任务单 C 路径的要求「反思里必须写清如果我要改造，会换掉哪个组件、为什么」，我选的不是换实现，而是**给现有实现加一道后置校验**。

**问题从哪来**：本次实测发现，0.5B 本地模型会无视 `build_prompt()` 里那句「资料中没有的内容就如实说'资料中未提及'」，转而把「结构清晰、语法准确、语境理解」这类通用套话包装成依据（见 [answer_log.md](../week08_助手v1.0/answer_log.md) 记录 1）。检索片段确实没命中相关内容，模型仍然答得像有据可查。

**官方与 llm-universe 的最小示例默认「模型会照资料答」**——它们没有对这个失败做处理，因为默认用云端大模型时这条指令基本能生效。我用 0.5B 本地模型就必须自己兜。

**改造方案（三步，都在已有接口上，不动 `answer()` 的结构）**：

1. `build_prompt()` 保留原有拒答措辞，但把「不要记忆补充」提到第一句——降低被后续内容稀释的概率。
2. 生成后检查答案里是否出现 `[S编号]` 标记。**一个都没出现，说明模型没引用任何检索到的片段**，视为可疑答案。
3. 此时在输出里追加一句「本次回答未引用任何检索片段，请人工核对」，把判断权交回使用者。

**为什么可行**：`assistant_v1.py` 的 `answer_details()` 已经把 `answer` 与 `sources` 分开返回，`invalid_citations` 也已经在算了——第 2、3 步要的数据接口都已存在，只差一次比较和一次拼接。

**状态：尚未实现，列为 v1.1 待办。** 这里如实标注，不把计划写成已完成。

### 另一个我想换的组件

**给 `get_store()` 加一个显式的 `collection_name` 参数**。现在集合名是 `corpus_signature()` 算出来的哈希（如 `w7_a1b2c3…`），机器可读性差——我想在 W9 把它换成有语义的命名（如 `w8_hsk_gf0025_nomic`），并在 README 里写明当前集合名与重建方式。否则换语料时新旧集合混在同一个数据库里，排查起来全靠猜。

这个改动只影响 `get_store()` 一处，`retrieve()` 与 `answer()` 的调用方式不变——这正是官方那句「组件可替换」的具体含义。
